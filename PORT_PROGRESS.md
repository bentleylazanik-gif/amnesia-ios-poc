### HPL2 renderer integration constraints

- `HPL2/core/include/graphics/LowLevelGraphics.h` declares 97 pure-virtual methods across initialization/capabilities, font/GPU-program/texture/vertex-buffer/framebuffer creation, render-target copies/clears, depth/alpha/stencil/blend/scissor/clip state, matrix stacks, texture units/environments, immediate drawing, and vertex batching. `cLowLevelGraphicsSDL` in `HPL2/core/include/impl/LowLevelGraphicsSDL.h` implements this broad interface; it is not a small renderer plugin seam.
- Startup is hardwired: `HPL2/core/sources/engine/Engine.cpp::CreateHPLEngine` handles only `eHplAPI_OpenGL` and creates `cSDLEngineSetup`; `SDLEngineSetup.cpp` creates the SDL system/graphics/input/resource/sound/physics backends and instantiates `cLowLevelGraphicsSDL`. `amnesia/src/game/LuxBase.cpp::InitEngine` explicitly requests `eHplAPI_OpenGL`.
- Even a purportedly simple HPL2 scene is not yet a shader-free Metal triangle: `HPL2/core/sources/graphics/Graphics.cpp` creates and loads `cRendererDeferred`, `cRendererWireFrame`, and `cRendererSimple`; `cRendererSimple::LoadData()` in `RendererSimple.cpp` loads `deferred_base_vtx.glsl` and `deferred_base_frag.glsl`. `LuxBase.cpp` also configures deferred G-buffers. Those shader/asset files are absent from this checkout.
- Resource/data mapping needed for a later Metal backend: `iVertexBuffer` in `graphics/VertexBuffer.h` defines element-array creation, vertex/color/index upload, compile/update, bind/draw/indexed draw, and copies; `iTexture` in `graphics/Texture.h` defines bitmap/raw/cube creation, update, filter/wrap/mipmap and compare state; `iFrameBuffer` in `graphics/FrameBuffer.h` defines 2D/3D/cube color/depth attachments and validation; `iGpuProgram` in `graphics/GPUProgram.h` defines shader linking, sampler/uniform/matrix binding. Desktop implementations are `VertexBufferOGL_Array.cpp`, `VertexBufferOGL_VBO.cpp`, `SDLTexture.cpp`, `FrameBufferGL.cpp`, `GLSLShader.cpp`, and `GLSLProgram.cpp`.
- A concrete production call path begins in `HPL2/core/sources/graphics/MeshCreator.cpp::cMeshCreator::CreatePlane`: create `iVertexBuffer` with triangle drawing and dynamic usage, define position (4 floats), normal (3), color (4), and UV (3), add 4 vertices and 6 indices, compile tangents, then attach the result and a material to `cSubMesh`. This makes the vertex-buffer contract a more useful first HPL2-to-Metal seam than a synthetic triangle. The path then depends on `iLowLevelGraphics::CreateVertexBuffer`, `cResources` material/animation managers, and renderer submission.
- Submission trace: `cRendererSimple::LoadData()` selects flat and diffuse variants of `deferred_base_vtx.glsl`/`deferred_base_frag.glsl` via `UseUv`, `UseNormals`, `UseColor`, and `UseDiffuse`; those shader files are absent. `cRendererSimple::RenderObjects()` runs a Z prepass then diffuse/decal/translucent sections, with depth/write/color-mask/alpha/blend differences. `iRenderer::BeginRendering()` clears color/depth and sets the frustum projection; `iRenderFunctions::SetMatrix()` submits view×model as ModelView. The Z pass binds material alpha at texture unit 0; the color pass binds diffuse at unit 0. GLSL binds declared samplers to texture units; there is no explicit sampler-object bind in this path. `SetProgram` binds `iGpuProgram`, `SetTexture` calls low-level texture binding, `SetVertexBuffer` binds HPL2 input, and `DrawCurrent()` calls `iVertexBuffer::Draw()` (OpenGL VBO uses unsigned-int indexed draw and stored topology/count). Thus a real simple-pass Metal path must implement projection/modelview, pipeline selection, depth/cull/color masks, Z-prepass alpha behavior, diffuse texture/sampler, and indexed submission; deferred adds G-buffer, stencil, shadow, and post effects.
- State details verified against `LowLevelGraphicsSDL.cpp` and `RenderFunctions.cpp`: low-level OpenGL init defaults depth compare `LessOrEqual`, depth writes on, cull backfaces; `eCullMode_CounterClockwise` maps to `glFrontFace(GL_CW)` because HPL's enum maps into the fixed GL front-winding setting (the `Clockwise` case selects GL_CCW). Alpha-test default is `GreaterOrEqual` at reference `0.6`; `RendererSimple`'s Z pass only toggles alpha testing on and does not call `SetAlphaLimit`, so the existing reference is retained. `SetBlendMode` factor pairs are Add=(One,One), Mul=(Zero,SrcColor), MulX2=(DestColor,SrcColor), Alpha=(SrcAlpha,OneMinusSrcAlpha), PremulAlpha=(One,OneMinusSrcAlpha). `eMaterialChannelMode` writes RGBA/RGB/alpha/none. Texture filters are Nearest/Bilinear/Trilinear; wraps are Repeat/Clamp/ClampToEdge/ClampToBorder. A Metal adapter must explicitly reject or emulate unsupported border/clamp semantics rather than silently approximating them.
